# 03 — Единицы и округление

### U01 — Длина: целые mm10
Внутри ядра длина хранится **целым числом десятых долей миллиметра**: 16 мм = 160, 1.5 мм = 15.
Так же устроен корневой движок (`engine/core/units.ts`). Дробей в графе нет, поэтому споров
«остался 0.1 мм» нет.

### U02 — Углы, массы, плотности
Угол хранится целыми десятыми градуса (110° = 1100). Масса хранится целыми граммами, плотность —
целыми кг/м³, нагрузка — целыми ньютонами или граммами по паспорту (единица объявлена в паспорте).

### U03 — Деление с остатком по объявленному правилу
Делить можно только функцией `0-base/units/divide`: результат — целые части, **сумма которых
точно равна целому**. Куда уходит остаток, решает ключ профиля `residualPolicy` (сейчас
`leftmost-absorbs`: первая часть). Пример: 1000 мм на 3 равные ячейки = 10000 mm10 → 3334 + 3333 + 3333.

### U04 — Сравнение без допусков
Числа сравниваются точно. Ключ профиля `epsilonMm` и «tolerance 1» (DATA N3) ядром **не**
используются: при целых mm10 допуск не нужен. Допуск остаётся у Полигона на его стороне
(старые кухни корпуса) и не протекает в ядро.

### U05 — Перевод только на границе
mm10 → мм переводит одна функция в `9-bridge` (деление на 10, точно до 0.1 мм). Четверть мм
SWJ008 — забота экспорта Полигона. UI переводит сам для показа и не записывает обратно.

### U06 — Ввод пользователя
Пользователь вводит мм с точностью до 0.1. Ввод 0.05 → отказ `REF-PRECISION` (ядро не округляет
молча, P03).
