# 05 — Слова (GENOME v1, заморожены)

15 слов: SELECT ×2, CUBE, SPLIT, DRAG, PLACE, MOUNT, GROUP, SAVE, SCOPE, REPLACE и 4 марки.
Для каждого слова указано: **делает · получает · меняет · НЕ имеет права менять · отказы ·
предупреждения · доказывают** (сценарии красной команды `RT xx`, [redteam](../redteam/README.md)).

Оси: x слева направо, y снизу вверх, z спереди назад. Все размеры в mm10 (U01).
Общие отказы для **любого** слова: `REF-MISSING-REF` (ссылка на несуществующий узел),
`REF-AMBIGUOUS` (нужно было бы угадать), `REF-PRECISION`, `REF-OUT-OF-SCOPE-APP1/APP3`.

---

### W01 — SELECT space
- **Делает:** выбирает пространство или ячейку фасада как цель следующей команды.
- **Меняет:** ничего в графе (выбор — состояние UI, не журнала).
- **Доказывают:** —

### W02 — SELECT part
- **Делает:** выбирает одну или **несколько** деталей / экземпляров (мультивыбор, Q16).
- **Меняет:** ничего в графе.

### W03 — CUBE
- **Получает:** w, h, d; контекст из App 1 (опора, стены, соседи); профиль.
- **Делает:** создаёт Module, 4 доски каркаса (L, R, T, B) по **стратегии** профиля (сейчас дно и
  крышка между боковинами) и пространство S0 внутри них. Перед и зад открыты.
- **Задник:** свойство модуля `back` = `overlay | groove | none | по правилу`. «По правилу»
  (значение по умолчанию) = модуль закрыт фасадом → `backMode` профиля; открыт → нет задника
  (решение основателя, вопрос 3). Задник появляется или исчезает как деталь свойства и **всегда**
  попадает в отчёт G15 с причиной.
- **НЕ меняет:** другие модули; ничего не добавляет сверх 4 досок (и задника по свойству).
- **Отказы:** `REF-TOO-SMALL` (меньше `minCarcassMm`).
- **Предупреждения:** `WARN-SUPPORT` (L4), если контекст из App 1 не объявил опору.
- **Доказывают:** RT J1, RT J6, RT C2.

### W04 — PATTERN (прежнее имя SPLIT)
- **Получает:** одну из пяти операций (создать · доли · вставить · убрать · распустить), см.
  [3-words/pattern](../3-words/pattern/README.md) и правило идентичности R04. Распределение описывает
  **промежутки** (Q70); тип участника — данные, не роль.
- **Делает:** создаёт **связанное деление** (Division) и его ячейки. Ячейки перечисляются снизу
  вверх / слева направо / спереди назад. Доля перечисляет **ячейки**: `1:1:1` = 3 ячейки и 2 доски.
  Несколько `flex` делят остаток поровну (Q25). Остаток при делении — по U03.
  На **плоскости фасада** ячейки берут зазоры профиля (поле по краю, зазор между; во вложенном
  делении только внутренние зазоры, Q20). С границей-деталью каждая граница фасада **проецирует**
  доску внутрь, по центру зазора: фасад ведёт (Q18).
- **Пересплит** того же пространства переопределяет то же деление (G20). `[1×1]` снимает деление (Q26).
  Если все предметы остаются в ячейках, они перераспределяются в новые ячейки (Q32) с отчётом.
  Если ячейка стала ниже короба ящика, этот ящик получает блокирующее `WARN-REFLOW-HEIGHT`, его
  короб не строится, пока пользователь не решит.
- **Паттерн-заполнение (фасады).** Хозяин — сам **юнит**, а не пространство внутри: фасад живёт на
  ГРАНИ (`fill: { type, face }`). Тогда ячейка — это не пустота, а **створка**: каждая ячейка
  получает деталь. Разрешена одна ячейка (одностворчатая дверь) — это не «деление ни на что».
  Доли меняют **число створок**. Поперёк оси створка берёт весь юнит минус поле. Если App 1 сказал,
  что боковина общая с соседом, фасад закрывает **половину** стойки; если юнит стоит отдельно —
  боковину целиком.
- **Меняет:** деление, ячейки, доски-границы; положения содержимого ячеек по перераспределению.
- **НЕ имеет права:** двигать или удалять предмет, у которого пропадает ячейка; менять доску,
  спроецированную фасадом; менять что-либо вне своего пространства.
- **Отказы:** `REF-ORPHAN` (Q19, Q26), `REF-NO-ROOM` (fixed-ячейки не помещаются),
  `REF-CUTS-PROJECTION` (внутреннее деление режет спроецированную доску, Q27), `REF-TOO-SMALL`.
- **Предупреждения:** `WARN-REFLOW-HEIGHT` (Q32).
- **Доказывают:** RT E1, RT E2, RT E3, RT E4, RT E5, RT H2, RT H3, RT H5, RT J2.

### W05 — DRAG
- **Делает:** (а) грань или ребро в своей плоскости → меняет размер; (б) ребро **поперёк** грани
  на A° → наклон вокруг противоположного ребра; (в) `S to <ref> [+mm]` → перенос пространства целиком.
- **Перетаскивание одной детали паттерна:** она **отвязывается** (Q68), паттерн делится на два,
  меняются только два соседних промежутка, остальные закрепляются своим размером (Q54). Вся
  семантика живёт в слове PATTERN, DRAG только передаёт ей сдвиг.
- **Перетаскивание фасада** в делении ящиков: фасад ведёт, короб следует (Q11).
- **НЕ имеет права:** менять размер, помеченный 🔒; двигать детали вне тянутого узла, кроме
  выведенных из него по объявленным связям (все в отчёте G15).
- **Отказы:** `REF-LOCKED`, `REF-NO-ROOM`, `REF-TOO-SMALL` (Q8), `REF-CYCLE`, `REF-OVERLAP` (L1a).
- **Доказывают:** RT A1, RT A2, RT A3, RT A4, RT A5, RT B7, RT H1.

### W06 — PLACE (доска) и `+` (предмет каталога)
- **Доска:** `PLACE type=t <пролёт> · <пролёт> · <связь>` — **одна** доска, пролёты по двум осям.
  Связь обязательна (направления по умолчанию нет, DECISIONS §9.4):
  - `against <грань доски>` → доска лежит на грани, толщина растёт **от** неё;
  - `on <плоскость> inside|outside` → на открытой плоскости (грань пространства, ячейка фасада,
    пол, стена) внутрь или наружу; без `inside|outside` → `REF-AMBIGUOUS`;
  - `covers <ячейка фасада>` → фасад: ячейка задаёт все три оси, лежит на плоскости фасада снаружи.
- **Толщина:** объявленная (у предмета с собственной геометрией, например проставка 25) главнее
  толщины листа; иначе из слота и профиля.
- **Деталь может выйти за пространство** (свес, боковина до пола), если связь так говорит,
  геометрия верна, есть опора и нет пересечения (DECISIONS §9.3).
- **Предмет:** `+ "item" → <пространство | ячейка фасада>` создаёт экземпляр (C-правила). Якорь по
  умолчанию: низ, у задней стенки, слева (Q30). Сохранённая группа ячеек деления переносит правило
  деления и перераспределяется в новом хозяине (Q29, Q31).
- **Главная функция App 2:** любая доска 16 мм где угодно (DECISIONS §10.2). Слов вроде
  `ADD_RAIL_80` нет.
- **НЕ имеет права:** добавлять вторую деталь; менять существующие детали.
- **Отказы:** `REF-OVERLAP` (L1a), `REF-AMBIGUOUS`, `REF-TOO-SMALL`.
- **Предупреждения:** `WARN-SUPPORT` (висит в воздухе, L4), `WARN-STOCK` (L3).
- **Доказывают:** RT J3, RT J4, RT J5, RT I5.

### W07 — MOUNT
- **Получает:** цель (деталь, группа или **пространство**), паспорт, необязательное положение
  в форме ссылки PLACE.
- **Делает:** цель получает движение, состояния и блокировки паспорта; отверстия появляются на
  **обеих** соприкасающихся гранях; строка BOM.
- **НЕ имеет права:** менять форму, размер или число деталей цели (P06); добавлять подложку.
- **Отказы:** `REF-HW-REQUIRES` (требование паспорта не выполнено) с перечнем паспортов, которые
  подошли бы; `REF-OVERLAP` (фурнитура на фурнитуре, X11).
- **Предупреждения:** `WARN-NO-SUBSTRATE` (нет доски под площадкой, H03), `WARN-MOTION-HIT` (L1b),
  `WARN-DOORHIT` (R75).
- **Статус:** поле паспорта отсутствует → `DATA INCOMPLETE (missing: поле)`.
- **Доказывают:** RT I1, RT I2, RT I3, RT I4, RT I5, RT I6.

### W08 — GROUP
- **Делает:** создаёт список узлов для совместного управления; `добавить`, `убрать`, `распустить`.
- **Меняет:** только список. Геометрия не меняется никогда (Z10), группа ничем не владеет (R13).
- **Отказы:** `REF-MISSING-REF`, `REF-AMBIGUOUS` (пустая группа, узел уже в ней).
- **Доказывают:** тесты `3-words/group`.

### W09 — SAVE (и `release`)
- **Делает:** группа становится элементом каталога (уровень: компонент / тип / модуль / набор,
  марки) и превращается в BOUND-экземпляр версии 1.
- **`release`:** отвязывает экземпляр (DETACHED: копирует текущие объявления, связи больше нет)
  или **извлекает** связанное деление (позиции записываются как собственные отступы, DECISIONS §2.4).
- **Отказы:** `REF-CYCLE` (определение содержит само себя).
- **Доказывают:** RT B4, RT B5, RT H4.

### W10 — SCOPE
- **Получает:** узел или поддерево, ключ, значение. Ключи: толщина, материал (слот), кромка и
  **ключи стратегии профиля** (дно, крышка, задник) — расширение GEN4 §3.
- **Делает:** записывает значение на уровень узла цепочки (S-правила). Самый узкий уровень побеждает.
- **Цели (R50):** эта деталь · все детали типа · группа · весь юнит · этот стык. Условие
  разрешается **один раз** в список uid, он и попадает в журнал (R51); новые детали старого
  изменения не получают (R52).
- **Ключи:** `слот` (материал через слот проекта, E12) · `способ` стыка · `насквозь` (R37).
- **Досягаемость:** толщина и материал корпуса доходят **только до досок**; задник и дно ящика
  из ХДФ сохраняют свои 3 мм (Q28).
- **НЕ имеет права:** менять внешний размер модуля.
- **Всё или ничего:** если новое значение где-либо в поддереве даёт отказ, SCOPE отказывает целиком.
- **Отказы:** `REF-OUT-OF-RANGE`, `REF-NO-ROOM`, `REF-OVERLAP`.
- **Доказывают:** RT F1, RT F2, RT F3, RT F4, RT F5, RT B1.

### W11 — REPLACE
- **Получает:** деталь, группу, экземпляр (= ячейку, в которой он стоит, DECISIONS §9.11) **или
  смонтированную фурнитуру** (расширение GEN4 §3); заменяет на предмет или на `nothing`.
- **Делает:** `nothing` = удаление по G16. Замена ставит новый предмет в **тот же** хозяин, хозяин
  не меняется.
- **НЕ имеет права:** удалять зависимые (G16), менять хозяина.
- **Отказы:** `REF-HAS-DEPENDENTS`, `REF-TOO-SMALL`, `REF-NO-ROOM`.
- **Доказывают:** RT C1, RT C2, RT C3, RT D1, RT D2, RT D3.

### W15 — ⚓ привязан к грани
Марки говорят, как часть определения ведёт себя при изменении хозяина. По умолчанию выводятся:
пересекает хозяина → ↔; размер задан материалом или фурнитурой → 🔒. Автор может переопределить.
Тип деления уже говорит о поведении (доля ≈ ↔, fixed ≈ 🔒, шаг ≈ ⋯, от края ≈ ⚓, DECISIONS §2.7).
- **Доказывают:** RT A3, RT B7.

## Мета-операции (не слова: пользователь их не «строит»)

### M01 — UNDO
Возвращает граф, побитово равный прежнему (G18). **Доказывают:** RT C4.

### M02 — REDO
Повторяет отменённую команду, результат тот же, что в первый раз (G17).

### M03 — SET PROFILE
Правка значения профиля. Значение вне диапазона → `REF-OUT-OF-RANGE`. Сначала отчёт о влиянии,
потом принятие (G19). **Доказывают:** RT G1, RT G2, RT G3.

### M04 — EDIT DEFINITION
Правка определения каталога = новая версия. Отчёт о влиянии, затем BOUND-экземпляры **этого
проекта** следуют (C04). **Доказывают:** RT B2, RT B3.

### M05 — APPLY UPDATE
Экземпляры в **другом** проекте закреплены на своей версии и получают «доступно обновление».
Меняются только после этой операции (C05). **Доказывают:** RT B6.

### M06 — RELEASE TO PRODUCTION
Передаёт модуль в Полигон. Закрыт, пока есть блокирующие находки. `DATA INCOMPLETE` выпуск не
закрывает, но требует **одного явного подтверждения** со списком всех допущений, и этот список
печатается на каждом листе. **Доказывают:** RT G4.
