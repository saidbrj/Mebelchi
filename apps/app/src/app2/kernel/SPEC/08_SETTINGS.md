# 08 — Настройки

### S01 — Четыре слоя
| Слой | Знает | Где | Тест, куда относится число |
|---|---|---|---|
| **ENGINE** | математику | код ядра, **без чисел** | — |
| **RULES** | логику | этот SPEC | — |
| **PROFILE** | выбор *этого* цеха, каждое значение с диапазоном | `things/profiles/<цех>/def.json` | два цеха могли бы не согласиться → PROFILE |
| **DATA** | факты покупной вещи | паспорта `things/hinges`, `slides`, `lifts`, `materials`… | производитель напечатал → DATA |

### S02 — Цепочка переопределений
`PROFILE → TYPE (определение каталога) → MODULE → INSTANCE → LOCAL (узел)`. Побеждает самый узкий
уровень. Каждое переопределение явное, видимое и считаемое («1 переопределение»). Каждое
разрешённое значение помнит, какой уровень его дал (G13).

### S03 — Слоты материала
Деталь ссылается на **слот**, а не на материал: корпус `A1, A2…`, фасад `F1, F2…`,
столешница `W1…` (App 1). Сменили F1 → поменялись все детали F1.

### S04 — Кромка = тип детали × слот
**Положение ребра** (видимое · скрытое · контактное · ударное) вместе с **типом детали** даёт
**толщину** через профиль. **Слот материала** даёт **цвет**: F1 → E1, F2 → E2, A1 → EA1. Кромку по одному ребру
никто не назначает. Смена F2 перекрашивает и фасады, и их кромку (DECISIONS §10.6).

### S05 — У каждого значения диапазон
Значение вне диапазона → `REF-OUT-OF-RANGE` уже при вводе (M03). Никто не введёт плотность 2000 и не
получит молчаливые ошибки. Значение с пометкой `assumed` или `test` делает результат
`DATA INCOMPLETE`, а не просто PASS.

### S06 — Настройки функции объявлены рядом с функцией (A04)
`<имя>.settings.ts` перечисляет ключи. Страж проверяет: каждый объявленный ключ есть в профиле
или паспорте, значение в диапазоне, диапазоны объявления и профиля совпадают.
