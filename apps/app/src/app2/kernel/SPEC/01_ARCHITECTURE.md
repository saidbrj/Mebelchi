# 01 — Архитектура

### A01 — Ядро над Полигоном, а не вместо
Ядро — новый слой. Полигон (`src/poligon`, 41 модуль, 899 тестов) остаётся back end'ом
производства: раскрой, кромка, сверление, System 32, SWJ008, PDF/XLSX/DXF. Ядро импортирует
Полигон, Полигон ядро — нет.

### A02 — Слои и направление импорта
`0-base` → `1-graph` → `2-settings` → `3-words` / `4-constraints` → `5-laws` → `6-components` →
`7-hardware` → `8-motion` → `9-bridge`. Файл слоя N импортирует только слои с номером меньше N
(и свой слой). Код Полигона импортирует только `9-bridge`. **Файлы настроек** Полигона
(`src/poligon/things/**/def.json`) читает только `2-settings` — это тот же файл профиля, второй копии нет.
Исключение: `3-words` вызывает проверки из `5-laws` и `6..8` через **реестр проверок** в `1-graph`
(слова регистрируют, законы подключаются), поэтому прямых импортов вверх нет.

### A03 — Одна функция = одна папка из 5 файлов
`README.md` · `<имя>.ts` · `<имя>.settings.ts` · `<имя>.findings.ts` · `<имя>.test.ts`.
Большая функция делится на соседние файлы, у каждого свой тест. Ориентир ~250 строк на файл.

### A04 — Файл настроек объявляет, но не хранит
`<имя>.settings.ts` перечисляет ключи, которые функция читает: ключ, слой (PROFILE / DATA),
единица, диапазон, кто владеет. **Значений в нём нет.** Значения лежат в
`src/poligon/things/profiles/<цех>/def.json` и в паспортах. Так у числа одно место (P04), а UI
настроек строит свои поля из объявлений.

### A05 — На вход только команды
Ядро не разбирает текст. Жест UI и фраза ИИ превращаются в один и тот же типизированный
`Command`. Парсер живёт вне ядра.

### A06 — Чистые функции
Каждая функция ядра — `(вход) → выход`, без глобального состояния, времени, случайности и сети.
Один и тот же журнал команд даёт побитово один и тот же граф (G17).

### A07 — Стражи (папка `guards/`)

| Страж | Ловит | Фаза |
|---|---|---|
| id SPEC уникальны; каждая ссылка сценария / теста ведёт на существующий id | висячие ссылки | 0 ✔ |
| GOLDEN-RULE рекурсивно по `kernel/**/*.ts` (кроме тестов, `0-base/units`, `redteam/`) | число в коде | 2 |
| направление импорта (A02) | импорт вверх | 2 |
| пять файлов в каждой папке функции (A03) | функция без описания или тестов | 2 |
| ничего автоматически (P01, G14) | лишняя деталь после команды | 2 |
| отказ не меняет граф (P02, G11) | частичное выполнение | 2 |
| каждый id W/L/Q покрыт тестом | правило без доказательства | 4 |
| одна правда (O-таблица): величину читают только через хозяина | вторая правда | 4 |
