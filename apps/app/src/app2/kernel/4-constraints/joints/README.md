# joints — стыки (SPEC E14, R05, R34, Z06, Z07)

Стык **выводится из геометрии**: он есть везде, где две детали соприкасаются гранями.
Хранить его не нужно — узел появляется только тогда, когда мастер изменил этот стык, и тогда
переопределение видно, считается и отменяется (R34).

```
   боковина        полка                боковина
   ┌──┐   ┌──────────────────┐   ┌──┐
   │  │◄──┤ стык J: полка × боковина ├──►│  │
   │  │   └──────────────────┘   │  │
   насквозь идёт боковина: у полки здесь торец
```

**Кто идёт насквозь** не угадывается: насквозь идёт та деталь, к **грани** которой пришла вторая.
Если детали сложены пластями (проставка к боковине), сквозной нет ни у кого.

**Имя стыка — это его место:** пара деталей. Пока обе детали живы, стык тот же самый (R05).
Заменили деталь — старый стык закрылся, появился новый, а местное изменение переносится или
называется потерянным (R37).

**Способ соединения** приходит из профиля по паре типов (`tables/part-types`, поле `joints`),
а мастер меняет его на конкретном стыке — это и есть режим стыков (E15).

## Перекрестье и сквозность (R37)

Две доски **под прямым углом** могут пересекаться: стык говорит, кто сквозной, а второго режут.
Две доски в одной плоскости пересекаться не могут — это по-прежнему отказ `REF-OVERLAP`.

- **Умолчание — ранги профиля** (`tables/junction-rank`: боковина 70 > перегородка 40 > полка 30),
  поэтому результат **не зависит от порядка команд**.
- Мастер переключает сквозность на конкретном стыке словом SCOPE.
- **В модели деталь остаётся одной**, uid не трогается. На отрезки она распадается только в
  раскрое: `P5.1`, `P5.2` — имена производные ([joints.segments.ts](joints.segments.ts)).

```
насквозь перегородка                 насквозь полка
P5.1 полка   200 × 16                P5  полка       568 × 16
P5.2 полка   352 × 16                P6.1 перегородка 16 × 300
P6  перегородка 16 × 688             P6.2 перегородка 16 × 372
```
