# Карта архитектуры и дорожная карта движка

Одна страница, чтобы полный план движка никогда не потерялся. Подробности — в [SPEC/](SPEC/README.md).

## 1. Кто над кем

```
   APP 1                    APP 2                     APP 3
   вся мебель: SET,         один UNIT — ячейка:       одна деталь / компонент:
   MODULE (общие детали),   пространства, паттерны,   вырезы, пазы как форма,
   расстановка юнитов,      компоненты, детали,       фаски, окно в двери,
   стены, цоколь, подвес    стыки, фурнитура          рамка Шейкер
        │                        │                         │
        │ контекст модуля:       │ команды (15 слов)       │ определение компонента
        │ опора, стены, соседи   │                         │ (форма детали)
        ▼                        ▼                         ▼
 ┌─────────────────────────────────────────────────────────────────────┐
 │                      ОБЩЕЕ ЯДРО  (src/kernel)                        │
 │  0 основа → 1 граф → 2 настройки → 3 слова → 4 марки → 5 законы →    │
 │  6 компоненты → 7 фурнитура → 8 движение → 9 мост                    │
 │  хранит: ЧТО объявлено · выводит: ГЕОМЕТРИЮ · проверяет: ЗАКОНЫ      │
 └─────────────────────────────────────────────────────────────────────┘
        │ готовые детали (размер, положение, роль, слот, монтаж)
        ▼
 ┌─────────────────────────────────────────────────────────────────────┐
 │                      ПОЛИГОН  (src/poligon)                          │
 │  раскрой · кромка · сверление · System 32 · листы · ZIR · выпуск     │
 └─────────────────────────────────────────────────────────────────────┘
        │
        ▼
   CUT · DRILL · EDGE · DXF · SWJ008 · PDF · XLSX
```

Сбоку, не в потоке данных: **профиль цеха и паспорта** (`src/poligon/things/`) читают и ядро,
и Полигон — это одни и те же файлы. **Судья MIND** не участвует ни в чём: он только подсказка для тестов.

## 2. Кто чем владеет

| Вопрос | Ответ |
|---|---|
| **Что где живёт** | Объявления (что сделал пользователь) — граф ядра, `1-graph`. Выбор цеха — `things/profiles/qorasu/def.json`. Факты покупных вещей — `things/hinges`, `slides`, `lifts`, `materials`. Каталог компонентов — `6-components` (фаза 7). Производство — `src/poligon`. |
| **Что где считается** | Геометрия (размер и положение каждой доски и пространства) — `1-graph/evaluate`, заново после каждой команды. Законы L1–L5 — `5-laws`. Раскрой, отверстия по паспорту, листы — Полигон. Привязка к растру 32 — ядро; Полигон только проверяет (O06). |
| **Кто кому передаёт данные** | App 1 → ядро: контекст модуля. App 3 → ядро: определение компонента. UI / ИИ → ядро: команды (`kernel/index.ts`). Профиль → ядро: через `2-settings` (толщина с происхождением). Ядро → Полигон: готовые детали через `9-bridge`. Полигон → файлы для станков. |
| **Кто владеет размером** | Объявленный размер (габарит 600, fixed 300) — **граф** (команда пользователя). Выведенный размер (боковина 720, полка 568) — **вычисление ядра**. Полигон размер не пересчитывает (O02, P04). |
| **Кто владеет профилем** | **Файл профиля цеха.** Ядро и Полигон его только читают. Меняется одной операцией M03: вне диапазона → отказ; принятая правка сначала показывает отчёт о влиянии (G19). |
| **Кто владеет геометрией** | **Ядро** (`evaluate`). Каждое число знает, откуда оно: «толщина 16 ← profile:qorasu carcassThicknessMm». |

## 4. Что уже умеет ядро (фаза 2)

| Команда | Пример | Что проверено тестами |
|---|---|---|
| CUBE | 600 × 720 × 560 → 4 доски + пространство 568 × 688 × 560 | стратегия стыка из таблицы рангов; второй модуль → App 1 |
| SPLIT | S1 по y `1:1:1` с полками → 218.8 / 218.6 / 218.6 | остаток по профилю; пересплит сохраняет uid; снятие; занятое → REF-ORPHAN |
| PLACE | полка `on S1.bottom inside +300` | связь обязательна; against растёт от доски; пересечение → REF-OVERLAP |
| DRAG | габарит 600 → 800; полка +40; доска деления → её ячейка постоянная | доска корпуса → REF-LOCKED с подсказкой; 0.05 мм → REF-PRECISION |
| Профиль | толщина 16 → 18 | отчёт о влиянии до правки; поломка → WARN-EXTERNAL-CONFLICT; вне диапазона → отказ |
| UNDO | любой шаг | возвращает ту же сессию, побитово |
