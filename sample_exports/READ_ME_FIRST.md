# Mebelchi — SWJ008 Sample Exports (Factory READ Test)

**Purpose:** check whether Excitech (or any CAM shell you have) can *open and read*
files produced by the Mebelchi engine. **This is a load/parse/simulate test only —
do NOT cut real material.**

These files were generated by our engine's `exportSWJ008` from the factory's **own**
panels, so the geometry is already known-good. If the software opens them and shows
the right panels and holes, our **file format** is proven compatible.

## The files

| File | What it is | Why |
|---|---|---|
| `POLKA-1_7_1.XML` | **Control.** Byte-for-byte identical to the factory's original POLKA file. | If this opens but ours don't, the problem is our format — but it's identical, so it must open. |
| `YON_BAK-1_4_1.XML` | Left side panel — edge drilling (Type 1) + face holes (Type 2). | Tests horizontal edge drilling + Z. |
| `POL_3_1.XML` | Bottom panel — through-drills on 3 edges + face holes. | Tests multi-edge machining. |
| `ORTA_BAK_6_1.XML` | Middle panel — drilling on **both** faces (Face 5 and Face 6). | Tests double-sided machining. |
| `MEBELCHI_ALL_PANELS.XML` | All 4 panels in **one** document. | Tests whether the shell reads multiple `<Panel>` per file (factory files are 1 panel each). |

## How to run the test at the factory

1. Copy this folder to the machine/CAM PC (USB).
2. In Excitech / the CAM shell, **Import / Open** each `.XML`.
3. For each, confirm on screen (not on the machine):
   - Panel **dimensions** are right (e.g. POLKA = 486 × 503 × 16 mm).
   - **Holes appear** in the right places, right count.
   - Hole **diameters / depths** read correctly (Ø15 / Ø8 / Ø5, depth 11 / 12.5 / 34 mm).
   - **Face** mapping is right (Face 5 = top, Face 6 = bottom, 1–4 = edges).
   - **Edge banding** shows on the right edges.
4. Run **air-cut / dry-run simulation** if available. **Stop there.** No spindle, no board.

## What to write down (bring back)

- Did each file **open without error**? If not, copy the exact error text.
- Any field the shell **ignored or complained about** (a missing attribute it wanted?).
- Does it want a **different file extension** (`.xml` lowercase? something else)?
- Does it want **one panel per file** only, or is the combined file fine?
- Does it expect a **different encoding** (these are ASCII text, declared `utf-8`, CRLF
  line endings — tell me if it wants Windows-1251 or anything else)?
- Which **machine/post** the shop actually runs (Excitech/KDT? Homag? Biesse?) — if it's
  Homag/Biesse it may want **MPR/BHX/DXF** instead of SWJ008; I can add that exporter.

## Notes

- These are **declarative geometry** (the machine sandboxes them), not motor code — the
  safe format by design. The real safety gate is still: load → simulate → only then cut.
- Right now the engine emits **SWJ008 only**. DXF / MPR exporters are not built yet; ask
  me and I'll add the one your shop needs once we know the target.
